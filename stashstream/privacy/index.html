StashStream Privacy Policy

Effective date: October 16, 2026

StashStream privacy and support contact: onellromandev@gmail.com

Scope

This policy describes StashStream, a client for a Stash media server that you choose and are authorized to access. The StashStream developer does not provide media content, host your media, or provide Stash servers. The server and its content are supplied by you or by another operator you choose.

This policy describes the current StashStream app for iPhone and iPad. Platform-specific details appear below. Planned platforms are not represented as released or audited. Before another platform is released, its actual storage, permissions, purchases, diagnostics, and service providers must be added to this policy if they differ.

Your server and media

When you connect, browse, search, or play media, the app sends requests directly to your configured server and retrieves library metadata, artwork, preview images, and media. Requests may include your API key, search terms, filters, media identifiers, and the library changes you request. Preview artwork may be requested while you browse, before you start a video.

When the server's activity-tracking configuration enables it, playback can send resume positions, viewing duration, and play-history updates to that server. Offline viewing can store progress on the device and synchronize it after reconnection. Features such as favorites, Watch Later, tags, collections, markers, and server jobs can read or change server records when used. The server operator controls its accounts, access permissions, logs, backups, retention, and deletion practices.

The current Apple app has no separate StashStream account registration or developer-operated library relay. The developer does not operate a Stash hosting service. Its normal library requests are not routed through a StashStream developer backend. This does not prevent your server operator, reverse proxy, hosting service, or media endpoints from processing the requests. Their network services can receive your IP address, request details, and user-agent information. Server-provided media or artwork URLs may use other hosts.

Connections and protection

Public server addresses require HTTPS in the current Apple app. Explicit HTTP is permitted for recognized local-network addresses. Local HTTP does not encrypt the API key, requests, or media in transit. Use a trusted network and an HTTPS server configuration when possible.

An API key may be included in a playback URL so that the server can authorize streams and HLS segments. Such URLs can be visible to the media-serving infrastructure or its logs. Avoid sharing authenticated playback links. StashStream cannot promise that every server, redirect, playlist endpoint, proxy, or external playback route has the same security or logging behavior.

The app uses Apple's Keychain and file-protection facilities for the data described above. Offline download files and the thumbnail-cache directory are marked to be excluded from backups. Other app preferences may be included in device backups according to your operating-system settings. The optional app PIN and background privacy cover limit casual access and app-switcher visibility; they are not a promise of end-to-end encryption, protection from every screenshot, or protection of the server itself.

The app uses local-network access to reach a configured local server and checks network availability to select between configured local and remote endpoints. Platform playback features, if you choose to use them, may send media to the output device or receiver you select.

Purchases and platform services

For the Apple app, Apple handles App Store purchases, billing, and subscription management. StashStream uses StoreKit to obtain product information and verified entitlement information, including product and transaction identifiers, expiration or revocation status, and subscription status where applicable. The app does not ask you to enter payment-card details into StashStream.

Family Sharing is shown only when the relevant product is reported by StoreKit as shareable. This is not a promise that every product or store configuration supports it. The current app does not retrieve a family-members contact list or share your Stash server credentials or media library through this feature. Apple controls its store records and retention under Apple's privacy policy.

Any purchase provider for a future platform will be identified here before that platform is released. Cross-platform purchase sharing is not implied.

Diagnostics, analytics, and support

The StashStream developer does not collect crash reports or analytics from your use of the app. The current Apple app does not integrate an advertising SDK, advertising-identifier tracking, or a third-party analytics/crash-reporting SDK. The in-app Connection Diagnostics tool sends read-only checks to your configured server. Its displayed results use fixed categories rather than displaying server addresses, API keys, scene titles, file paths, or response bodies, and those diagnostic results are cleared when the diagnostics view is closed. This is not an automatic report upload to the developer.

Other app error messages and system-generated diagnostics can still contain technical information; do not assume that every screenshot or diagnostic file is free of private content. Apple may independently process device, purchase, usage, crash, or beta-testing information through its platform services according to its settings and terms. Apple or a user-operated server processing information is distinct from the developer collecting crash reports or analytics.

If you email onellromandev@gmail.com, the developer receives your email address, message, and any attachments you choose to send to handle your support request. This mailbox uses Google's Gmail service; Google's handling of the service is described in Google's privacy policy. Do not send API keys, authenticated links, or private media. Technical details that you voluntarily send become part of your support correspondence; they are not an automatic crash-reporting or analytics feed.

Support emails are retained in the mailbox until the user explicitly requests their deletion. There is no automatic deletion schedule. To request deletion, email onellromandev@gmail.com and identify the correspondence you want deleted. This describes the developer's mailbox practice, not the retention of records independently controlled by Apple, Google, GitHub, or your server operator.

Retention, deletion, and your choices

  • Server data: use the server's controls or contact its operator to access, correct, export, or delete server accounts, media, history, and backups. Disconnecting or deleting StashStream does not delete those records.
  • Connection: Disconnect removes the saved connection profile and requests removal of its API key from this installation's Keychain. Revoke or rotate the key at the server if you need to invalidate it there. Disconnect is not a complete local-data erasure feature.
  • Downloaded video: use Downloads to remove local downloads. Disconnecting does not automatically erase downloaded videos, their metadata, or pending offline progress. Remove downloads before disconnecting if you intend to erase them. Removing a download does not remove the server's original file.
  • Thumbnail cache: use Settings → Thumbnail Cache → Clear Cache to remove disposable cached thumbnails. This does not delete downloaded videos. Cache entries have an expiration of at most 24 hours and may be removed earlier because of server cache directives, space limits, account changes, or manual clearing. Expiration is not a guarantee that every file is physically erased at an exact clock time; cleanup occurs during cache activity.
  • PIN: disable the app PIN through its settings when authorized to do so. Disconnect does not disable it. Keychain records and device backups can have a lifecycle different from the app's ordinary files; uninstalling is not presented here as a guarantee of erasing every record.
  • Preferences and older local records: some preferences and migration records remain until changed or the app's local data is removed. There is no verified one-button erasure of all local and server information.
  • Platform records: Apple purchase, subscription, backup, and diagnostic records are managed through Apple's controls and policies. Deleting the app does not cancel a subscription.

For privacy questions or a request to delete your support correspondence, contact onellromandev@gmail.com. The developer cannot directly erase a server operated by someone else. No fixed deletion deadline, automatic retention period, or special retention exception is promised.
